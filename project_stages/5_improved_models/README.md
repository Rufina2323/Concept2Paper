# Дополнение к baseline: GNN-модели для предсказания связей концептов

Это дополнение к baseline-решению: добавление графовых моделей (GNN) и сравнение их с ранее обученными baseline-моделями.

---

## 1. Изменения в пайплайне данных

К существующему пайплайну добавлен один артефакт: граф концептов, построенный **только из тренировочного окна**. Используется как вход для GNN.

### Защита от утечки данных

Валидационные и тестовые пары **не входят в рёбра** обучающего графа. Это исключает leakage метки через message passing — GNN не «видит» целевые рёбра во время агрегации соседей.

---

## 2. Новые архитектуры

### GNN+MLP

Реализованы две графовые модели поверх `torch_geometric` (`GNNLinkPredictor`):

| Модель | Pairwise-фичи |
|---|---|
| GNN+MLP (gnn+emb) | `emb` |
| GNN+MLP (gnn+struct+emb) | `structure + emb` |

**Архитектура:**

1. **Encoder** — GNN-стек обучает векторное представление каждого узла-концепта по его многошаговому окружению в графе.
2. **Pairwise head** — для пары `(a, b)` подаётся `[node_emb(a) ‖ node_emb(b) ‖ pairwise_features(a, b)]` в MLP с dropout.
3. **Loss** — `contrastive` (унифицирован с MLP-моделями для честного сравнения).

Идея: GNN добавляет «дальний» контекст соседства, который ручные структурные признаки (общие соседи, AA, Jaccard) не охватывают.

---

## 3. Постобработка предсказаний (новое для GNN)

В дополнение к стандартной постобработке baseline:

- **Маппинг вершин** — `concept_to_idx` строится один раз на train-графе; для пар из ranking-набора используется `c2i.get(concept, 0)` с fallback на индекс 0 для холодных узлов.
- **Раздельные входы predict** — GNN-модель принимает `(vertex_pairs, pairwise_features)`, в отличие от baseline `(X)`. В ноутбуке оценки это учтено единым интерфейсом `predict_fn(df, X)`.
- **Кэш `GNNData`** — на одну фичовую группу строится одна копия графа и узловых фич, переиспользуется обеими GNN-моделями (`gnn+emb` и `gnn+struct+emb` различаются только `pairwise_features`).

---

## 4. Анализ качества GNN-моделей

### Результаты на `ranking_test.csv`

| Модель | ROC-AUC | MRR | nDCG@5 | nDCG@10 | nDCG@50 | nDCG@100 |
|---|---:|---:|---:|---:|---:|---:|
| GNN+MLP (gnn+emb) | 0.8365 | 0.0385 | 0.0000 | 0.0000 | 0.0324 | 0.0276 |
| **GNN+MLP (gnn+struct+emb)** | 0.8599 | 0.1111 | 0.0000 | **0.1299** | 0.2875 | 0.2613 |

### Подробный разбор

**1. `GNN+MLP (gnn+emb)` — слабая модель.**
ROC-AUC = 0.837 (худший показатель среди всех 7 моделей), nDCG@100 = 0.028. GNN-эмбеддинги уже несут структурный сигнал, а `emb`-фичи дают семантическую близость — эти источники **перекрываются** и не дают сильных дискриминативных pairwise-признаков. Без ручных структурных фич модель остаётся «слепа» к точным локальным индикаторам типа AA-индекса.

**2. `GNN+MLP (gnn+struct+emb)` — сильный результат на глубоких отсечках.**
nDCG@10 = 0.130, nDCG@50 = 0.288, nDCG@100 = 0.261 — на больших k практически догоняет лидера `MLP (all)` и **существенно обходит `XGBoost (all)`** (у которого nDCG@100 = 0.054). Это прямое подтверждение: ручные структурные признаки и GNN-эмбеддинги **дополняют, а не дублируют** друг друга.

**3. Почему GNN не побила `MLP (all)`.**
Гипотезы:
- **холодный старт** — у части тестовых концептов мало рёбер в train-графе, GNN-агрегация даёт слабый сигнал;
- **унифицированная архитектура** — pairwise-голова, dropout и loss взяты как у baseline-MLP для честности сравнения, без отдельного тюнинга под GNN;
- **малый объём данных** относительно ёмкости GNN-encoder.

**4. Эффект на top-K.**
nDCG@5 = 0 у обеих GNN-моделей: на самой верхушке выдачи они уступают `XGBoost (all)`. GNN сильна на средних/глубоких отсечках, но не даёт «острого» top-1/top-3.

### Обновлённый итог по семейству моделей

| Сценарий | Рекомендуемая модель |
|---|---|
| Top-5 / top-10 (короткий список) | `XGBoost (all)` |
| Длинный top-K, скоринг | `MLP (all)` |
| Глубокое ранжирование с учётом графа | **`GNN+MLP (gnn+struct+emb)`** |

### Что подтвердили GNN-эксперименты

- Гипотеза «структурные признаки критичны» подтверждена и на графовых моделях: `gnn+emb` слабее `gnn+struct+emb` на всех метриках.
- GNN не вытеснила лидера baseline (`MLP (all)`), но показала конкурентное качество на глубоких отсечках и открыла направление для дальнейших улучшений.

### Направления дальнейшего развития

- **Тюнинг GNN**: глубина, типы свёрток (GAT, GraphSAGE), размер узловых эмбеддингов, раздельные learning rate для encoder и head.
- **Ансамбль `XGBoost` (острый top-K) + `MLP (all)` / `GNN+MLP (gnn+struct+emb)` (глубокий хвост)** — покрытие обоих режимов выдачи.
- **Обогащение узловых фич** в GNN (текстовые эмбеддинги концептов как initial node features вместо обучаемых с нуля).
