# Анализ датасета ICLR для извлечения концептов и link prediction

## 1. Источник датасета и состав данных

### Источник данных
Датасет взят из [GitHub Repository](https://github.com/berenslab/iclr-dataset/tree/main).
Датасет состоит из публикаций конференции ICLR (International Conference on Learning Representations) за 2017–2025 годы с метаданными.

ICLR является одной из ведущих конференций в области машинного обучения и искусственного интеллекта, поэтому данные хорошо подходят для построения графа научных концептов и анализа эволюции исследовательских направлений.

### Размер датасета

После загрузки исходный датасет содержит:

* **55 906 записей**
* **10 исходных признаков**

После фильтрации по году (`year < 2026`) и отбора только принятых статей:

* **11 349 accepted papers**

### Структура данных

| Поле         | Описание                                          |
| ------------ | ------------------------------------------------- |
| `year`       | Год публикации / сабмита                          |
| `id`         | Уникальный идентификатор статьи                   |
| `title`      | Название статьи                                   |
| `abstract`   | Аннотация статьи                                  |
| `authors`    | Список авторов                                    |
| `author_ids` | Идентификаторы авторов                            |
| `decision`   | Решение конференции (accept/reject/workshop/etc.) |
| `scores`     | Reviewer scores                                   |
| `keywords`   | Авторские ключевые слова                          |
| `labels`     | Тематические метки статьи                         |

### Предобработка

В ноутбуке были выполнены следующие шаги preprocessing:

1. Преобразование поля `keywords` в список строк.
2. Создание статистических признаков:

   * длина abstract,
   * количество слов в abstract,
   * длина title,
   * количество слов в title,
   * количество keywords.
3. Нормализация decision labels.
4. Создание бинарного признака `is_accepted`.
5. Отбор только принятых статей для дальнейшего анализа.

Для задачи извлечения концептов будут использоваться только accepted papers, так как:

* они отражают научно валидированные направления;
* шум от слабых/некачественных работ уменьшается;
* граф концептов становится более устойчивым;
* снижается вероятность появления нерелевантных концептов и случайных связей.

| 2023 | 4955              |
| 2024 | 7401              |

### Выводы

1. Наблюдается экспоненциальный рост количества сабмитов.
2. В более поздних годах существенно выше разнообразие концептов.
3. Граф концептов будет динамическим и нестационарным.
4. Для link prediction важно учитывать temporal split, так как распределение тем меняется со временем.

Поэтому для обучения модели будет использоваться:

* train: 2017–2022 → predict 2023
* val: 2017–2023 → predict 2024
* test: 2017–2024 → predict 2025

Такой split предотвращает temporal leakage.

## 2.2 Распределение решений

Исходные decision labels содержат большое количество вариаций:

* Reject
* Withdrawn
* Accept (Poster)
* Accept (Oral)
* Accept (Spotlight)
* Workshop track
* Desk rejected
* и др.

После упрощения категории были сведены к:

* Accept
* Accept (Poster)
* Accept (Oral/Spotlight)
* Reject
* Withdrawn
* Workshop

### Выводы

1. Датасет сильно несбалансирован.
2. Rejected и withdrawn papers составляют значительную долю.
3. Для extraction pipeline использование rejected papers может ухудшать качество концептов.
4. Использование только accepted papers является оправданным решением.

# 3. Оценка качества разметки и предложения по улучшению

## 3.1 Текущее качество разметки

### Keywords

Плюсы:

* авторские ключевые слова обычно семантически значимые;
* отражают ключевые концепты статьи;
* хорошо подходят как weak labels.

Минусы:

1. Сильная вариативность написания.
2. Наличие синонимов.
3. Разный уровень детализации.
5. Некоторые ключевые слова слишком общие:

   * deep learning,
   * AI,
   * machine learning.

### Labels

Проблемы:

1. Большая доля `unlabeled`.
2. Нужно размечать вручную для других статей.
3. Labels не отражают комбинации концептов.

---

## 3.2 Риски для extraction pipeline

Без дополнительной обработки extraction может приводить к:

* concept duplication;
* semantic fragmentation;
* noisy edges;
* inflated graph sparsity.

Примеры:

* “LLM” vs “Large Language Models”
* “Diffusion” vs “Diffusion Models”
* “RLHF” vs “Reinforcement Learning from Human Feedback”

---

## 3.3 Рекомендации по улучшению

### 1. Canonicalization

Необходимо приводить концепты к canonical form:

* lowercasing,
* lemmatization,
* acronym expansion,
* synonym merging.

Желательно поддерживать отдельный словарь `alias mapping`.

---

### 2. Ontology-aware normalization

Можно использовать:

* CSO (Computer Science Ontology),
* PapersWithCode taxonomy,
* Semantic Scholar topics.

Это позволит:

* объединять близкие концепты;
* удалять overly generic concepts;
* строить более устойчивый граф.

---

### 3. LLM-based extraction

Рекомендуемый pipeline:

1. Input:

   * title,
   * abstract.

2. LLM extraction:

   * методы,
   * архитектуры,
   * задачи,
   * domains,
   * datasets,
   * optimization approaches.

3. Post-processing:

   * normalization,
   * deduplication,
   * filtering generic concepts.

---

### 4. Confidence filtering

Для каждого extracted concept желательно сохранять:

* confidence score,
* extraction source,
* mention frequency.

Низкоуверенные концепты можно исключать.

# 4. Формирование выборки и стратегия валидации

## 4.1 Постановка задачи

После extraction каждая статья преобразуется в набор концептов.

Далее строится граф:

* узлы = концепты;
* ребра = совместная встречаемость концептов в одной статье.

Если concepts A и B встречаются в одной статье, создается edge:

* A ↔ B

Вес ребра определяется по совместной встречаемости (co-occurrence frequency).

---

## 4.2 Формирование графа

### Узлы

Каждый уникальный концепт.

### Ребра

Ребро создается, если:

* концепты встречаются совместно минимум в одной принятой статье.

Возможные ограничения:

* минимальная частота концепта;
* минимальная частота ребра.

---

## 4.3 Temporal split

Предлагаемая схема:

| Stage      | Graph period | Target     |
| ---------- | ------------ | ---------- |
| Train      | 2017–2022    | edges 2023 |
| Validation | 2017–2023    | edges 2024 |
| Test       | 2017–2024    | edges 2025 |

### Почему это корректно

1. Полностью соблюдается причинность.
2. Нет утечки данных из будущего.
3. Модель оценивается в реалистичной среде прогноза новых связей между концептами.

---

## 4.4 Positive/Negative edges

**Positive samples**:

* новые ребра, появившиеся в новом году;
* ребра, отсутствовавшие ранее.

Пример:

Если: “diffusion models” и “LLM” не были связаны до 2023, но появились совместно в 2023, то это positive edge для train.

**Negative edges**:

* пары концептов без новых связей в следующем году.


---

## 4.5 Рекомендуемые модели

Для downstream link prediction подходят:

### Classical

* Node2Vec + MLP
* Adamic-Adar
* Common Neighbors
* Personalized PageRank

### Graph ML

* GraphSAGE
* GAT
* SEAL
* VGAE
* Temporal GNN
* Dynamic Graph Transformer

### LLM-enhanced

* text embeddings концептов;
* semantic edge scoring;
* hybrid graph-text models.

---

## 4.6 Метрики

Для оценки link prediction:

* ROC-AUC
* MRR
* NDCG@k

# Итог

Датасет ICLR хорошо подходит для задачи построения графа концептов благодаря:

* большому количеству статей;
* временной структуре;
* разнообразию исследовательских направлений;
* наличию аннотации и ключевых слов.

Наиболее перспективный пайплайн:

1. Извлечение концптов на основе LLM.
2. Нормализация концептов.
3. Построение графа концептов, учитывая время их появления.
4. Предсказание связей с учетом времени.
5. Генерация новых комбинаций концептов.
6. Использование LLM для генерации черновиков абстрактов на основе предсказанных связей.
