# Baseline-решение: предсказание новых концептов в научных статьях

Цель baseline — построить полный воспроизводимый пайплайн от сырых статей до предсказания новых пар связанных концептов с количественной оценкой качества.

---

## 1. Загрузка и очистка данных

### Пайплайн

Этапы запускаются последовательно: каждый шаг читает выходы предыдущего.

**Stage 1 — Извлечение концептов**
```bash
uv run python -m src.extract_concepts
```
Извлекает сырые концепты из научных статей.

**Stage 2 — Нормализация концептов**
```bash
uv run python -m src.normalize_concepts
```
Дедуплицирует и нормализует извлечённые концепты.

**Stage 3 — Построение датасетов концептов**
```bash
uv run python -m src.create_concept_datasets
```
Собирает датасеты в формате, готовом для построения графа знаний.

**Stage 4 — Обучение и оценка моделей предсказания связей**
```bash
uv run python -m src.run_link_prediction
```
Обучает и оценивает модели link-prediction на графе концептов, чтобы находить новые пары концептов.

### Сравнение методов извлечения концептов

Для извлечения концептов было реализовано и сравнено **четыре метода**:

| Метод | Тип | Комментарий |
|---|---|---|
| **YAKE** | статистический | быстрый, но шумный |
| **RAKE** | статистический | плохо ловит многословные термины |
| **KeyBERT** | эмбеддинговый | лучше по семантике, но слабее на доменной лексике |
| **LLM-based** | генеративный | **лучший по качеству** — используется во всех последующих шагах |

Сравнительный анализ методов:

- `project_stages/4_baseline_models/data_analysis/concept_similarity_evaluation.ipynb` — анализ семантического сходства извлечённых концептов.
- `project_stages/4_baseline_models/data_analysis/keyword_analysis.ipynb` — анализ ключевых слов и покрытия терминологии.

На основе результатов сравнения дальнейшие шаги (нормализация, построение графа, обучение моделей) выполнены **на концептах, полученных LLM-based методом**.

## 3. Выбор моделей

Акцент в baseline сделан **не на сложности архитектуры, а на анализе разных групп признаков** для обучения. Это позволяет понять, какие сигналы (структурные, эмбеддинговые или их комбинация) наиболее информативны для задачи.

Использованы три типа признаков:

- **`structure`** — структурные признаки графа (степени вершин, общие соседи, индексы Жаккара/Адамика-Адара и т. п.).
- **`emb`** — эмбеддинговые признаки концептов.
- **`all`** — объединение `structure` и `emb`.

Обучены **5 моделей** на разных комбинациях признаков:

| Модель | Признаки | Назначение |
|---|---|---|
| MLP (structure) | только `structure` | базовая модель, оценка вклада структуры |
| MLP (emb) | только `emb` | базовая модель, оценка вклада семантики |
| **MLP (all)** | `structure + emb` | усложнённая модель — объединение признаков |
| LightGBM (all) | `structure + emb` | альтернативная модель (бустинг) |
| XGBoost (all) | `structure + emb` | альтернативная модель (бустинг) |

## 4. Оценка качества моделей

### Метрики

Для задачи ранжирования посчитаны **6 метрик** (две основные + nDCG на нескольких отсечках):

- **ROC-AUC** — качество бинарной классификации пар (есть связь / нет связи).
- **MRR** (Mean Reciprocal Rank) — насколько высоко в выдаче оказывается первый правильный кандидат.
- **nDCG@5, @10, @50, @100** — нормализованный дисконтированный прирост качества ранжирования на разных глубинах.

Сравнение моделей выполнено в ноутбуке:
`project_stages/4_baseline_models/evaluate_baseline_models.ipynb`

### Результаты на `ranking_test.csv`

| Модель | ROC-AUC | MRR | nDCG@5 | nDCG@10 | nDCG@50 | nDCG@100 |
|---|---:|---:|---:|---:|---:|---:|
| MLP (structure) | 0.8876 | 0.1000 | 0.0000 | 0.0636 | 0.1836 | 0.2104 |
| MLP (emb) | 0.8504 | 0.0233 | 0.0000 | 0.0000 | 0.0142 | 0.0242 |
| **MLP (all)** | **0.9074** | 0.2500 | 0.1461 | 0.0948 | **0.2972** | **0.2969** |
| LightGBM (all) | 0.8627 | 0.0167 | 0.0000 | 0.0000 | 0.0000 | 0.0081 |
| **XGBoost (all)** | 0.8904 | **0.5000** | **0.2140** | **0.2025** | 0.0882 | 0.0544 |

### Анализ результатов

**1. Лучшая бинарная разделимость — `MLP (all)`.** ROC-AUC = 0.907 показывает, что объединение структурных и эмбеддинговых признаков даёт лучший общий сигнал о наличии связи между концептами, чем каждая группа по отдельности (`structure`: 0.888, `emb`: 0.850).

**2. Структура важнее эмбеддингов для ранжирования.** Сравнение `MLP (structure)` и `MLP (emb)`:
- по ROC-AUC они почти равны (0.888 vs 0.850),
- но по MRR и nDCG структурные признаки превосходят эмбеддинги во всех точках отсечки.

Это значит, что эмбеддинги дают «грубую» семантическую близость, но плохо помогают выбрать **правильный конкретный** пары среди семантически близких.

**3. Топ-5 / топ-10 уверенно выигрывает `XGBoost (all)`.** MRR = 0.5, nDCG@5 = 0.214, nDCG@10 = 0.202 — на топе концептов это лучшая модель. Однако качество резко падает при увеличении k (nDCG@100 = 0.054).

**4. LightGBM показал слабый результат.** Несмотря на приличный ROC-AUC (0.863), все ранжирующие метрики около нуля. Вероятная причина — модель калибрована как классификатор, а не как ранжировщик.

### Совокупная оценка

Если **взвешивать качество по практической полезности для задачи**:

1. **XGBoost (all)** — лучший выбор для коротких рекомендательных списков (top-5/top-10).
2. **MLP (all)** — лучший выбор для скоринга на больших объёмах и стабильно высокого nDCG.
3. MLP (structure) — разумный лёгкий baseline.
4. MLP (emb) и LightGBM (all) — в текущей конфигурации непригодны для ранжирования.

### Выводы по baseline

- **Структурные признаки графа критичны** — без них модель видит только семантику и не отличает реально связанные концепты от семантически похожих.
- Лучший baseline-результат: **MLP (all) с ROC-AUC = 0.907 и nDCG@100 = 0.297**.
- Для top-K рекомендаций — **XGBoost (all) с MRR = 0.5 и nDCG@10 = 0.202**.
- Дальнейшее улучшение: добавить GNN-эмбеддинги.
