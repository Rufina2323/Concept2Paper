# Concept2Paper — гипотеза и прототип MVP

# 1. Ключевая гипотеза

## Формулировка гипотезы

Если мы предлагаем **веб-сервис генерации научных идей и драфтов абстрактов** на основе графа концептов и LLM  
для **ML/AI исследователей и аспирантов**,  
которые готовят идеи для публикации на конференциях уровня ICLR,  
то получим не менее **20% пользователей**, которые сохранят или экспортируют сгенерированный драфт абстракта после первой сессии  
в течение **2 недель тестирования MVP**,  
потому что сервис существенно **сокращает время поиска и формулировки новой исследовательской идеи**.

# 2. Ключевые метрики

## 2.1 Продуктовые метрики

| Метрика | Что измеряем | Baseline | Цель | Как измеряем | Частота |
|---|---|---|---|---|---|
| Draft Save Rate | Доля пользователей, сохранивших generated draft | 0 | ≥ 20% | Event tracking | Каждый день |
| Abstract Export Rate | Экспорт сгенерированного абстракта | 0 | ≥ 15% | Логи фронта | Каждый день |
| Session Completion Rate | Пользователь дошел до генерации идеи | 0 | ≥ 50% | Funnel analytics | Каждый день |
| Avg Time to Idea | Время от входа до результата | ~2–3 часа вручную | ≤ 10 минут | Timestamp events | Каждый день |
| Human Quality Score | Оценка экспертами (1–5) | 2–3 | ≥ 4 | Ручная оценка | Раз в неделю |
| Novelty Score | Насколько идея кажется новой | неизвестно | ≥ 60% положительных оценок | Экспертная оценка | Раз в неделю |

# 3. Что войдет в прототип, а что — нет

## Войдет в MVP

### 1. Загрузка и обработка статей ICLR

Почему:
- нужен ограниченный домен;
- проще валидировать качество.

### 2. Извлечение концептов

Методы:
- KeyBERT;
- TF-IDF;
- LLM extraction.

Почему:
- это ядро системы.

### 3. Построение графа концептов

- co-occurrence graph;
- weighted edges.

### 4. Предсказание новых связей

- Node2Vec + cosine similarity;
- простой link prediction baseline.

### 5. Генерация abstract

- через готовую LLM API;
- prompt на основе найденных концептов.

### 6. Простой веб-интерфейс

Пользователь:
- выбирает конференцию;
- получает идею;
- получает draft abstract.

---

## Намеренно НЕ делаем

### 1. Полноценный fine-tuning LLM

Почему:
- дорого;
- долго;
- не нужно для проверки гипотезы ценности.

### 2. Поддержку многих конференций

Почему:
- усложняет данные;
- снижает качество;
- MVP должен быть узким.

### 3. Полноценную recommendation system

Почему:
- не критично для проверки основной гипотезы.

### 4. Автоматическую генерацию full paper

Почему:
- слишком сложная задача;
- риск расползания scope.

### 5. GNN production-grade pipeline

Почему:
- сначала нужен baseline;
- важно проверить саму ценность идеи.

# 4. Какие готовые блоки используем, а что делаем сами

## Готовые инструменты

| Блок | Инструмент | Почему |
|---|---|---|
| Embeddings | Sentence Transformers | Быстро и качественно |
| Keyword extraction | KeyBERT | Хороший baseline |
| Графы | NetworkX | Быстрое MVP |
| Link prediction baseline | Node2Vec | Простая реализация |
| LLM generation | OpenAI API | Не нужно обучать свою модель |
| Frontend | React + Next.js | Быстрый веб MVP |
| Backend API | FastAPI | Быстро и удобно |
| Хранение | PostgreSQL / Neo4j | Графовые запросы |

---

## Что делаем сами

### 1. Логику генерации новых комбинаций концептов

Почему критично:
- это ключевая технологическая ценность проекта.

### 2. Prompt engineering

Почему:
- напрямую влияет на качество идеи и abstract.

### 3. Pipeline ranking идей

Почему:
- нужно фильтровать бессмысленные комбинации.

### 4. Evaluation framework

Почему:
- стандартных метрик недостаточно;
- нужна экспертная оценка новизны.

# 5. Главный риск, который проверяем прототипом

Главный риск:

> Пользователи не будут считать сгенерированные идеи и абстракты достаточно полезными и новыми для реального research workflow.

То есть технически система может работать хорошо, но:
- идеи будут банальными;
- abstract будет слишком generic;
- исследователи не увидят ценности.

Прототип должен проверить именно:
- возникает ли ощущение “это реально полезно”;
- экономит ли это время;
- готовы ли пользователи использовать это повторно.

---

# 6. Конечный формат прототипа

## Формат

Веб-приложение (MVP сайт).

## Пользовательский сценарий

1. Пользователь выбирает конференцию (ICLR).
2. Вводит область интереса:
   - например “diffusion models”.
3. Система:
   - находит концепты;
   - предлагает новые комбинации;
   - генерирует draft abstract.
4. Пользователь:
   - копирует;
   - сохраняет;
   - оценивает результат.

---

# 7. Критерии остановки теста прототипа

Тест MVP останавливаем, если выполняется хотя бы одно условие:

| Условие | Интерпретация |
|---|---|
| Draft Save Rate < 10% после 2 недель | Пользователи не видят ценности |
| Human Quality Score < 3/5 | Генерация слишком слабая |
| ≥ 50% экспертов считают идеи банальными | Нет новизны |
| Время генерации > 5 мин | UX неприемлем |
| Пользователи не возвращаются повторно | Нет product-market fit |

---

# Итоговая идея MVP

Прототип не пытается “писать научные статьи автоматически”.

Он проверяет более важную гипотезу:

> Можно ли с помощью графа научных концептов и LLM ускорить появление новых research ideas настолько, чтобы исследователи захотели использовать это регулярно.
